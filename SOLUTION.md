# Solution: Unit Test Agent and agentic PR workflow

A custom **Unit Test Agent** with five reusable **skills**, run by an **agentic workflow** on every pull
request. It analyzes the PR diff, decides per changed file whether to create, update or skip unit tests,
writes them for the FastAPI backend and React frontend, **verifies them by running them**, and posts a
report on the PR. The same agent was used to backfill missing tests across the existing code.

| | Before | After |
|---|---|---|
| Backend (pytest) | 21 tests, 42% coverage | 44 tests, **59%** |
| Frontend (Vitest) | 18 tests, 47.7% lines | 51 tests, **72.7%** |

## 1. Main technical decisions

| Decision | Rationale |
|---|---|
| **[GitHub Agentic Workflows](https://github.github.com/gh-aw/) (`gh-aw`)** as the agent environment | Native to GitHub: Markdown workflow compiled to Actions, built-in firewall, read-only agent job, and **safe outputs**, a separate job that performs writes only after validation. Engine-agnostic: switching models is a one-line change. |
| **Claude (Sonnet 5.5) engine**, `max-turns: 60` | Tried Copilot first (the fine-grained token was rejected with 401 on this account), then Gemini (free tier returned 503 on the newest model and allows 20 requests/day; one run needs 20–40). Claude completed every run, at $0.19–0.34 each. |
| **Agent = rules, skills = know-how + scripts** | The agent file holds the policy (when to create, update or skip, hard rules, security). Skills hold repo-specific recipes and **deterministic scripts**, so facts (what changed, what passed, coverage) come from code, not from the model. |
| **Report rendered from result files** | The PR comment is generated by `render_report.py` from JUnit XML, coverage JSON and mutation results. The model cannot overstate results, and a file without a decision is flagged. |
| **Verification is more than "tests pass"** | Each new test runs twice (flakiness), then a **mutation check** breaks the source and the test must fail, then the full suites run with typecheck and format checks. |
| **Independent CI without AI** (`tests.yml`) | Proves the agent's tests pass on a clean runner. The agent never checks itself. |
| **Two layers before any write** | (1) gh-aw AI threat detection (prompt injection, secret leaks, malicious patches); (2) a deterministic gate: the patch may only touch `backend/tests/**/*.py` and `frontend/src/**/*.test.ts(x)` and may not add `skip`/`only`/`xfail`. |

## 2. How to run the PR workflow

**Prerequisites**
1. Repository secret **`ANTHROPIC_API_KEY`** (an Anthropic API key with a spend limit).
2. *Settings → Actions → General → Workflow permissions:* keep **Read** as the default, and enable **"Allow GitHub Actions to create and approve pull requests"** (needed for backfill PRs).
3. To change the workflow: [`gh aw`](https://github.github.com/gh-aw/) CLI, then `gh aw compile` after editing `unit-test-agent.md`. Commit both the `.md` and the generated `.lock.yml`.

**Automatic (PR mode).** Open or update a PR from a branch of this repository that touches
`backend/app/**` or `frontend/src/**`. The agent pushes one test commit to the PR branch and comments with its report.
A new push cancels an outdated run for the same PR.

**Manual (backfill mode).** Raises coverage for existing code and opens a draft PR:
```bash
gh workflow run unit-test-agent.lock.yml -f scope=frontend/src/features/todos/hooks   # or 'all', or any path prefix
```

## 3. Where the agent and skills live, and how they are used

```
.github/
├── agents/unit-test-agent.agent.md        custom agent: role, decision policy, hard rules, security
├── skills/
│   ├── analyze-pr-changes/                diff → per-file plan (scripts/plan_changes.py)
│   ├── write-backend-tests/               pytest conventions of this repo (fixtures, autospec mocks, TestClient)
│   ├── write-frontend-tests/              Vitest + Testing Library conventions (design-system mocks, React Query wrapper)
│   ├── run-and-verify-tests/              verify.sh (targeted ×2 + full suites + coverage), mutation_check.py
│   └── report-results/                    render_report.py → PR comment from real result files
└── workflows/
    ├── unit-test-agent.md / .lock.yml     agentic workflow (gh-aw source + compiled Actions YAML)
    └── tests.yml                          plain CI: pytest + vitest + coverage, no AI
```

**Execution flow**

1. **Setup** (no AI). Install dependencies. Run `plan_changes.py` (**analyze-pr-changes**) to produce
   `.test-agent/plan.json`. Run the base branch's suites with coverage, so the report can show deltas.
2. **Agent job** (read-only token; firewall allows only `api.anthropic.com`; shell commands allow-listed).
   The workflow imports the agent file. The agent:
   - reads the plan and the diff, and decides per file;
   - writes tests using **write-backend-tests** / **write-frontend-tests**;
   - verifies with **run-and-verify-tests**;
   - renders the comment with **report-results**.
3. **Detection.** AI threat analysis plus the deterministic gate.
4. **Safe outputs.** Only now is the patch pushed to the PR branch (or opened as a draft PR) and the report posted.

## 4. Example run: feature PR #11 "filter todos by priority"

The feature adds `GET /api/todos?priority=…` (backend) and a Priority select (frontend). It was pushed
**without tests**. Plain CI went **red**: one router assertion and typechecking in two frontend test files broke.

[Agent run 42805955767](https://github.com/duza/taskly-app/actions/runs/42805955767) was triggered by the PR event: 42 turns, $0.34.

**Decisions**

| Changed file | Action | Reason given by the agent |
|---|---|---|
| `repository.py` | update | `list()` gained an optional priority filter |
| `router.py` | update | new query param; existing assertion updated because `list()` is now called with `priority=None` (**intended behaviour change**) |
| `utils/todos.ts` | update | `selectTodos` gained a priority filter |
| `hooks/useTodoFilters.ts` | update | new priority state combined with the other filters |
| `components/TodoFilters.tsx` | update | new Priority select |
| `TodosPage.tsx` | update | mocked hook needed the new fields to typecheck |
| `types.ts` | skip | type-only change, excluded from coverage |

- **Skills reported by the agent:** analyze-pr-changes, run-and-verify-tests, report-results. The test-writing skills were listed in the backfill runs (#7, #8, #10); here the agent extended existing test files in their established style.
- **Results:** 6 test files changed (+88 lines). Backend 44 passed, coverage 57.6% → 58.8%. Frontend 51 passed, 72.2% → 72.7%. Typecheck and format pass. Both detection layers passed, and commit `5171e3d` was pushed with the report comment.
- **Independent CI on the agent's commit: green** ([run 42807069892](https://github.com/duza/taskly-app/actions/runs/42807069892)).

**Backfill runs** using the same agent and skills:

| PR | Scope | Effect |
|---|---|---|
| #7 | `backend/app/core` | backend coverage 42.4% → 57.6% |
| #8 | `frontend/src/lib` | frontend coverage 47.7% → 54.3% |
| #10 | `frontend/src/features/todos/hooks` | frontend coverage 47.7% → 65.6% (each run measured from the same starting point) |

The agent also behaves correctly when it **cannot** finish. In one early run the shell allow-list
blocked its commands. It did not commit unverified tests: it reported *incomplete* with the reason.

## 5. Assumptions

- Unit tests only: no real database, network or browser; dependencies are mocked as in the existing tests.
- The agent may only add or modify test files. Production bugs are reported as findings, never fixed by the agent.
- PRs come from branches of this repository. Fork PRs are blocked by default, because they would run with this repository's secret.
- Coverage-excluded files (`schemas.py`, `models.py`, `types.ts`, design-system and others, per the project config) are skipped unless they contain logic.
- A human reviews and merges. The agent never merges.

## 6. Limitations

- **CI is not re-triggered by the agent's commit.** GitHub does not start workflows from pushes made with `GITHUB_TOKEN`, so `tests.yml` must be run manually (or a `GH_AW_CI_TRIGGER_TOKEN` added). The agent's own verification runs in the same job.
- **The mutation check is basic.** Simple operator and return-value mutations, applied to the whole file, not just changed lines. Files without such operators (for example `lifespan.py`, `useTodoFilters.ts`) get 0/0, which the report states.
- **The shell allow-list is defense in depth, not the main boundary.** Allowed interpreters (`python3`, `bash`, `npx`) can run arbitrary code inside the sandbox. The real boundaries are the firewall, the read-only token and the gated write job.
- **Model dependency.** Results vary between runs. Large scopes can hit the 60-turn cap, so backfills are split by path prefix.
- **`gh-aw` is in technical preview.** A long-lived `ANTHROPIC_API_KEY` secret is used.

## 7. What I would change for production

- **Keyless authentication:** Anthropic workload identity federation (GitHub OIDC) instead of a static API key.
- **A GitHub App token for safe outputs,** so agent commits trigger required CI checks and are attributed to a bot identity.
- **Diff-aware mutation testing** (only mutate changed lines), or an established tool (mutmut, Stryker), with a minimum kill rate as a gate.
- **Required checks and branch protection:** `tests.yml` required, and a coverage threshold for changed lines.
- **Cost and quality monitoring:** per-run cost, turns and acceptance rate of agent commits. Use cheaper models for small diffs.
- **Fork PRs:** a label-gated flow (`forks:` + author association) for trusted external contributors.
- **Faster runs:** cache dependencies, run only affected test files in the agent loop, and keep full suites in CI.
